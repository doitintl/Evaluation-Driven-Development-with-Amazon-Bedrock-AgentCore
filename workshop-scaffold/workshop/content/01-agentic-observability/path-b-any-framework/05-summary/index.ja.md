## 証明したこと

| 主張 | あなたの証拠 |
|---|---|
| 完全なトラジェクトリが捕捉されている | `aws/spans` へのクエリが、1 回の実行について `AGENT=1` と複数の `LLM`、`TOOL` スパンを表示した |
| 呼び出しごとのコストが見える | 各 `LLM` 行のトークン数。合成がツール選択よりはるかに高価だった |
| スパンは評価に対応している | モジュール 2 はまさにこれらのスパンを採点し、2 つ目のエクスポートは不要 |
| 他人のものではなく自分の実行が AWS に到達した | スパン内の `session.id` が、ターミナルに表示されたものと一致した |

:::alert{type="success" header="持ち運べる原則"}
エージェントの可観測性とは、リクエストと応答だけでなく **トラジェクトリ** を捕捉することです。AgentCore が理解するスコープの下でトラジェクトリがスパンに入れば、評価は追加コストなしで手に入ります。

具体的には、モジュール 4 でコーディングエージェントが 4 つ目のツールを追加したとき、その呼び出しは `TOOL` スパンとして現れ、自動的に採点されます。アダプターが名前付きのツールではなく *ライフサイクルイベント* を購読しているからです。
:::

:::alert{type="info" header="任意: 標準 OTEL ではこれができなかった理由"}
標準 OpenTelemetry の `gen_ai.*` 名前空間には、個々のモデル推論に対するセマンティック規約がありません。`invoke_agent` (実行全体) と `execute_tool` (各ツール呼び出し) は得られますが、その間の推論ステップは見えません。

OpenInference は `openinference.span.kind: "LLM"` でその隙間を埋め、`llm.model_name`、`llm.token_count.*`、入出力メッセージを保持します。アダプターは pi-mono の `message_start` / `message_end` イベントを購読し、各推論をそれらのスパンの 1 つにマッピングします。AWS は Strands 以外のフレームワーク向けにサポートされる計測ライブラリとして [OpenInference をドキュメント化](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability-configure.html) しています。
:::
