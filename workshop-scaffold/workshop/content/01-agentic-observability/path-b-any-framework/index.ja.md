## Path B: OpenInference で AWS GenAI Observability に完全な LLM トラジェクトリを送る

このパスでは **エージェントの完全なトラジェクトリ** を捕捉します。すべての LLM 推論呼び出し、すべてのツール実行を、呼び出しごとのトークン数とモデルの帰属情報とともに捉え、**OpenInference のセマンティック規約** を使って AWS CloudWatch GenAI Observability に直接送信します。

**OpenInference は、あらゆるエージェントフレームワークを計測するためのオープン標準です。** 同じスパンが AWS、Arize Phoenix、Langfuse、その他のバックエンドで機能します。このワークショップのサンプルエージェントは **pi-mono** (TypeScript) 上に構築されているため、すべてのステップが具体的でコピー & ペーストできますが、手法自体はフレームワークに依存しません。各ステップには、LangGraph、CrewAI、独自エージェントなどで何が変わるかを説明する **➡️ あなたのフレームワークの場合** の注記が含まれます。

### 素の OTEL ではなくオープンな規約を使う理由

標準の OpenTelemetry の `gen_ai.*` 名前空間はエージェントレベルとツールレベルの属性を定義していますが、**LLM 呼び出しごとのスパンに対するセマンティック規約がありません**。個々のモデル推論は、エージェントのスパン内部の不透明な作業になります。エージェントが実行された *こと* と、*どの* ツールを呼んだかは見えますが、*どの* モデル呼び出しがツール起動を決めたのか、各判断が何トークンかかったのか、レイテンシがどこに集中したのかは見えません。

**OpenInference** は、`openinference.span.kind: "LLM"` を専用のスパン種別として定義し、`llm.model_name`、`llm.token_count.*`、`llm.input_messages` / `llm.output_messages` を持たせることでこれを解決します。各モデル推論が、`AGENT` および `TOOL` スパンと並んで、トレースツリー内の可視でクエリ可能なスパンになります。

### 1 つのスコープで 2 つの役割

AgentCore は `openinference.instrumentation.*` のスコープファミリーをネイティブに理解します。**ダッシュボード向けに出力するのと同じスパンが、モジュール 2 で AgentCore Evaluation が採点するスパンです。** ツール名、引数、結果、最終的な回答はすべて OpenInference のスパンから直接読み取られます。2 つ目のスコープも、フレームワークの偽装も、別途エクスポートするログイベントも必要ありません。このパスは **すべてを 1 つのスコープで** 出力し、最初から評価可能です。

### このパスを使うとき

エージェントが Strands 上に構築されて **いない** 場合で、次を求めるときに Path B を選びます。

- **追加インフラを動かさずに** (Docker も外部プラットフォームも不要) LLM 呼び出しレベルの完全なトラジェクトリを得たい
- すべてを **1 つの AWS ダッシュボード** に集めたい (CloudWatch の GenAI Observability)
- **オープンでポータブルな標準** を使いたい (同じ OpenInference スパンが Arize Phoenix、Langfuse、AWS などで機能します)
- CloudWatch Transaction Search で呼び出しごとのトークン数とモデルの帰属情報を見たい
- 追加作業なしでモジュール 2 の **評価に対応した** テレメトリが欲しい

### 所要時間の目安

| ステップ | 時間 |
|------|----------|
| 概要 | 約 5 分 |
| 可観測性 CFN のデプロイ | 約 10 分 (スタックに 2 〜 4 分、その後 Transaction Search が `ACTIVE` になるまで 6 〜 10 分) |
| アダプターの構築 | 約 15 分 |
| 実行と確認 | 約 10 分 |
| サマリー | 約 5 分 |

**合計: 約 45 分。** デプロイのステップの大半は待ち時間で、その間に先を読み進められます。
