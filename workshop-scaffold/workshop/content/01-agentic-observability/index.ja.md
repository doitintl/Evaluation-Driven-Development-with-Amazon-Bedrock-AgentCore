## 課題

本番環境にエージェントがあり、ユーザーがそれと対話しています。しかし、エージェントが何をしているのか、どのツールを呼んだのか、どんな推論経路をたどったのか、ハルシネーションを起こしたのか、なぜ 1 セッションが 4 秒ではなく 40 秒かかったのかが見えません。可観測性がなければ、すべてのサポートチケットが考古学になります。何が起きたのかを再構成しようと、アプリケーションログを掘り返すことになります。

**このモジュールでそれを解決します。** 終了時には、エージェントのすべての呼び出しが次のものを生成します。

- **[AWS X-Ray](https://docs.aws.amazon.com/xray/latest/devguide/aws-xray.html) のトレース**: リクエストから応答までの **スパン** (それぞれが計時された作業単位) の完全なツリー。すべてのツール呼び出しを含みます。
- **CloudWatch のレコード**: 入力、出力、セッションコンテキストを含む正規のエージェントレコード。
- **GenAI Observability ダッシュボードのスパン**: エージェントのトラジェクトリ専用のビュー。

評価スコアはまだありません。モジュール 2 で、ここで構築したテレメトリの基盤の上に自動 LLM-as-Judge の採点を追加します。

## パスを選ぶ

現時点では、モジュール 0 で実行したときと同じく、エージェントは Code Editor の EC2 インスタンス上の通常のプロセスとして動いています。2 つのパスは **エージェントが最終的にどこに置かれるか** が異なります。

- **Path A はマネージドインフラ (AgentCore Runtime) に移します。** これは本番のエージェントを実際にホストする形に近く、注入される **サイドカー** (エージェントの隣で動き、コード側で対応しなくても済むようテレメトリを処理するヘルパープロセス) からテレメトリを取得します。
- **Path B はそのままの場所に残し**、手動で計測します。コンピュートを自分でホストする場合に行うことです。

どちらも同じ評価可能なテレメトリを生成し、どちらもおまけの選択肢ではありません。選択は 1 つの問いで決まります。**あなたのエージェントは Strands Agents SDK を使っていますか。**

| | パス | エージェントフレームワーク | 接続方法 | 所要時間 |
|---|---|---|---|---|
| **A** | [AgentCore Runtime 上の Strands](path-a-strands/) | Strands (Python) | AgentCore Runtime にデプロイ。マネージドなサイドカーが OTEL を出力し、計測コードは不要 | 約 20 分 |
| **B** | [その他すべてのフレームワーク](path-b-any-framework/) | それ以外すべて (このワークショップでは TypeScript フレームワークの **pi-mono** を使用) | エージェントのライフサイクルイベントを OpenTelemetry のスパンにマッピングする小さな OpenInference アダプターを追加 | 約 45 分 |

Strands 上で構築していて摩擦の少ない道を選びたい場合は **Path A** を選んでください。AgentCore Runtime のサイドカーがすべてのテレメトリを処理します。

それ以外 (LangGraph、CrewAI、社内の独自フレームワーク、あるいはこのワークショップのように pi-mono) で構築している場合は **Path B** を選んでください。**OpenInference** でエージェントを計測します。これは AgentCore の Observability と Evaluation の両方が理解するオープンなセマンティック規約の標準です。

:::alert{type="info" header="Path B と pi-mono について"}
このワークショップのサンプルエージェントは TypeScript のエージェントフレームワーク **pi-mono** 上に構築されているため、Path B はそれに即して具体的に書かれています。実在するファイル、コピー & ペーストできる実際のコマンドです。*手法* 自体 (エージェントのライフサイクルイベントを購読 → OpenInference のスパンを出力 → SigV4 で署名して AWS へ送信) はフレームワークに依存しません。Path B の各所に、エージェントが pi-mono でない場合に何が変わるかを示す **「➡️ あなたのフレームワークの場合」** の注記があります。
:::

どちらのパスも同一の結果に収束します。X-Ray のトレース、CloudWatch のエージェントレコード、GenAI Observability ダッシュボードのスパン。すべてが **評価可能** な状態です。そのため、どちらのパスを選んでもモジュール 2、3、4 は同じように動作します。

## どのパスでも行うこと

1. **概要**: これから構築するものの 1 ページの見取り図。
2. **可観測性インフラのデプロイ**: Transaction Search の配線と、エージェントの **ロググループ** (CloudWatch がログレコードを格納するコンテナ) のインデックスポリシーを作成する軽量な CloudFormation スタック。
3. **エージェントの接続**: 「Runtime をデプロイする」(Path A) から「OpenInference アダプターを追加する」(Path B) まで。
4. **呼び出しと確認**: エージェントを実行し、X-Ray にトレースが現れること、CloudWatch にレコードが届くこと、GenAI Observability ダッシュボードにスパンが表示されることを確認します。
5. **サマリー**: 振り返りと次の内容。
